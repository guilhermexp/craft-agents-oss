# Craft Embedded Hermes Runtime

Use this skill whenever the task involves Hermes running inside Craft Agents Electron, especially on a new user's computer, a packaged DMG/NSIS/AppImage, native Craft tools/MCPs, internal browser access, channels/War Room, meetings/Google Meet, or release validation.

This skill is intentionally repository-bundled seed knowledge. It must not depend on Guilherme's local `HERMES_HOME`, local memories, local profiles, local API keys, or local CLIProxyAPI process.

## Mental model

Craft embeds Hermes as a bundled Python/ACP runtime. A packaged app should work without the user installing Hermes separately.

There are three layers:

1. **Signed/bundled runtime** — immutable app resources shipped with Craft.
2. **User runtime state** — app-scoped `HERMES_HOME` created under Electron `userData` on each user's machine.
3. **Session-native tools** — Craft passes browser/source/session tools to Hermes through ACP `session.mcpServers`; these are per session and local-only.

Do not confuse these layers.

## Important paths

### In the Craft repo / dev checkout

```txt
Repo: apps/electron/../../
Bundled Hermes source: apps/electron/resources/vendor/hermes/
Hermes embed docs: apps/electron/docs/hermes-embed.md
Channels docs: apps/electron/docs/channels-war-room.md
Native seed skills: apps/electron/resources/hermes-seed/skills/
```

### In a packaged macOS app

```txt
Craft Agents.app/Contents/Resources/app/vendor/hermes/
Craft Agents.app/Contents/Resources/app/dist/resources/hermes-seed/
```

### Per-user app state

macOS:

```txt
~/Library/Application Support/@craft-agent/electron/hermes
```

Windows/Linux use Electron `app.getPath('userData')` plus `hermes/`.

This app-scoped home must be used instead of standalone `~/.hermes`.

## Runtime contract

Before claiming Hermes is available in Craft, verify or preserve these facts:

- `CRAFT_HERMES_PYTHON` points at bundled `vendor/hermes/hermes-venv/.../python`.
- `CRAFT_HERMES_ARGS` is `['-m', 'acp_adapter']`.
- `CRAFT_HERMES_HOME` points under Electron `userData/hermes`.
- `CRAFT_HERMES_AGENT_ROOT` points at bundled `vendor/hermes/hermes-agent`.
- Packaged builds set/follow `CRAFT_HERMES_REQUIRE_BUNDLED=1` when the bundled runtime is missing and must fail closed instead of falling back to a system `hermes` from PATH.
- `apps/electron/resources/vendor/hermes` is generated by `bun run bundle:hermes` and included by `electron-builder.yml` as `app/vendor/hermes`.

## New user bootstrap responsibilities

On a fresh user machine, the next Hermes should know that it is inside Craft only if Craft seeds or injects that context. A correct bootstrap should:

1. Resolve `HERMES_HOME` from `CRAFT_HERMES_HOME` or Electron `userData/hermes`.
2. Ensure `HERMES_HOME` exists.
3. Copy repository-bundled seed skills from app resources into `HERMES_HOME/skills/` if missing.
4. Preserve user edits. Never blindly overwrite user-created skills/profiles/config without a versioned migration or backup.
5. Keep secrets out of repository seed files. Credentials come from Craft Credential Manager/auth bridge at process spawn.
6. Expose Craft native tools through ACP `session.mcpServers`, not through a static global Hermes `mcp.json`.
7. Show health status in Craft Settings rather than assuming startup success.

Suggested seed location in the app bundle:

```txt
resources/hermes-seed/
├── skills/
│   └── craft-embedded-runtime/
│       └── SKILL.md
├── profiles/          # optional future defaults; avoid secrets
├── plugins/           # optional future Craft-specific plugins
└── manifest.json      # optional future version/merge policy
```

Suggested user copy target:

```txt
$HERMES_HOME/skills/craft/craft-embedded-runtime/SKILL.md
```

Craft startup should run the repository bootstrap/migration (`ensureHermesSeedSkills`) so `resources/hermes-seed` is the source of truth and fresh release users get the skill in Hermes' normal skill tree without manual copying.

## Native Craft tools / MCP rules

Craft-native tools are session scoped. Do not make them global Hermes tools by writing them into `mcp.json` as the primary path.

Expected ACP shape:

```txt
Craft session -> Hermes ACP session -> session.mcpServers -> local Craft MCP bridges
```

Canonical tool naming at the Hermes boundary:

```txt
craft-session tools: mcp__session__browser_tool, mcp__session__spawn_session, mcp__session__call_llm, ...
craft-sources tools: mcp__github__search_issues, mcp__filesystem__..., etc.
external MCP tools: normal Hermes names such as mcp_filesystem_read_file
```

Validation rule: an MCP port that responds to `initialize` only proves the server exists. Do not claim the tool bridge is usable until `tools/list` and at least one relevant `tools/call` succeed.

## Internal browser

Prefer Craft's internal BrowserView tool when available:

```txt
mcp__session__browser_tool
```

Validation target:

```txt
open/navigate to https://example.com
evaluate document.title
close/cleanup
```

If using an external OS/browser automation tool, explicitly say it is not Craft's internal browser.

## Channels / War Room

For channels, read or preserve:

```txt
apps/electron/docs/channels-war-room.md
```

Product invariants:

- A channel is a shared room surface; individual agent sessions are implementation details.
- Mentions like `@research`, `@server-ops`, or `@default` route work to participants.
- Worker results return to the same channel.
- Lead/orchestrator rooms should infer a Hermes lead if `leadParticipantId` is missing.
- Hermes Kanban uses app-scoped `HERMES_HOME` and profile-slug assignees.

## Meetings / Google Meet

There are two related paths:

1. Craft native meetings page / BrowserView.
2. Hermes `google_meet` plugin running a Playwright/Chromium bot.

Do not call the integration functional just because a Meet URL opens in the BrowserView. The bot must reach a real state such as:

```txt
lobbyWaiting=true
inCall=true
```

Prefer a dedicated bot Google account saved under app-scoped Hermes workspace, for example:

```txt
$HERMES_HOME/workspace/meetings/bot-auth.json
```

Do not bridge the meeting organizer's cookies as bot identity. Avoid printing cookies/localStorage/tokens in logs.

## Providers and model config

For release users, do not assume Guilherme's local providers exist.

In particular, a local OpenAI-compatible proxy such as CLIProxyAPI on `127.0.0.1:8317` is developer-specific. A packaged Craft install should:

- default to providers configured through Craft Credential Manager / LLM Connections;
- detect local proxy providers before offering them as active defaults;
- avoid shipping profiles that break because `127.0.0.1:<port>` is missing;
- keep API keys and OAuth tokens out of seed skills/config files.

## Release validation checklist

Before distributing a DMG/NSIS/AppImage that claims embedded Hermes support:

```bash
cd apps/electron
bun run bundle:hermes
bun run dist:mac   # or platform equivalent
```

Then validate on a clean user profile/machine:

1. Launch Craft without standalone Hermes installed.
2. Confirm logs contain `Hermes bundled runtime resolved`.
3. Confirm `HERMES_HOME` is under Craft's `userData/hermes`.
4. Start a Hermes-backed session.
5. Confirm ACP subprocess starts from bundled Python.
6. Confirm seed skills are present or the app clearly reports seed missing.
7. Confirm `tools/list` includes Craft session/source tools for the active session.
8. Call one benign session tool, preferably browser navigate/evaluate.
9. Open Hermes dashboard from Craft Settings.
10. Verify provider/auth UX uses Craft credentials and does not require manual `.env` files.

## Debugging logs safely

Never print secrets. Redact common token patterns before sharing logs.

Useful macOS log candidates:

```txt
~/Library/Logs/@craft-agent/electron/main.log
~/Library/Logs/Craft Agents/main.log
$HERMES_HOME/logs/agent.log
$HERMES_HOME/logs/errors.log
$HERMES_HOME/profiles/<profile>/logs/agent.log
```

Redaction shell pattern:

```bash
RED='s/(AIza)[A-Za-z0-9_-]+/$1...REDACTED/g; s/(xai-)[A-Za-z0-9_-]+/$1...REDACTED/g; s/(fc-)[A-Za-z0-9_-]+/$1...REDACTED/g; s/(sk-[A-Za-z0-9_-]+)/sk-...REDACTED/g; s/(Bearer )[A-Za-z0-9._-]+/$1...REDACTED/g'
tail -200 "$HOME/Library/Logs/@craft-agent/electron/main.log" | perl -pe "$RED"
```
