Usage: react-doctor [options] [command] [directory]

Diagnose React codebase health

Arguments:
  directory                     project directory to scan (default: ".")

Options:
  -v, --version                 display the version number
  --lint                        enable linting
  --no-lint                     skip linting
  --dead-code                   enable dead-code analysis (default)
  --no-dead-code                skip dead-code analysis (unused files / exports
                                / dependencies, circular imports)
  --supply-chain                enable the dependency supply-chain scan
                                (default)
  --no-supply-chain             skip the dependency supply-chain scan
                                (Socket.dev dependency health checks)
  --verbose                     show every rule and per-file details (default
                                shows top 3 rules)
  --debug                       force a Sentry trace and print its id at the end
                                (paste it into a bug report)
  --output-dir <dir>            directory for the full diagnostics dump
                                (default: a temp folder)
  --score                       output only the score
  --json                        output a single structured JSON report
                                (suppresses other output)
  --json-compact                with --json, emit compact JSON (no indentation)
  --json-out <path>             with --json, write the report to a file instead
                                of stdout
  -y, --yes                     skip prompts, scan all workspace projects
  --no-parallel                 lint serially with one worker (default: parallel
                                across CPU cores; set the worker count with
                                REACT_DOCTOR_PARALLEL)
  --project <name>              select projects: workspace names or directory
                                paths (comma-separated for multiple); overrides
                                the `projects` config field
  --scope <value>               how much supported JS/TS source to scan/report:
                                full (default), files, changed (only new issues
                                vs base), or lines (issues whose source spans
                                touch changed lines)
  --base <ref>                  base git ref for files/changed/lines scope
                                (auto-detected when omitted)
  --include-untracked           with --scope files/changed/lines, also scan
                                ordinary untracked files (respects .gitignore)
  --no-score                    skip the score API, the share URL, and crash
                                reporting
  --category <category>         only show diagnostics in a category (repeatable;
                                e.g. Security)
  --no-telemetry                alias for --no-score (skip the score API, share
                                URL, and crash reporting)
  --staged                      scan only staged (git index) files for
                                pre-commit hooks
  --max-duration <seconds>      scan time budget for the whole run, shared
                                across workspace projects: past it, remaining
                                lint batches and dead-code are skipped and
                                partial results are reported (skipped files are
                                listed in the JSON report)
  --blocking <level>            severity that fails CI: error (default),
                                warning, or none (advisory)
  --no-respect-inline-disables  audit mode: neutralize inline lint suppressions
                                before scanning
  --warnings                    show warning-severity diagnostics (default)
  --no-warnings                 hide warning-severity diagnostics (errors only)
  --color                       force colored output
  --no-color                    disable colored output (also honors NO_COLOR)
  -h, --help                    display help for command

Commands:
  design [directory]            Run only the focused UI design diagnostics
  why [options] <location>      Explain why a rule fired (or why a suppression
                                didn't apply) at a file:line
  install|setup [options]       Install the react-doctor skill into your coding
                                agents and optional git hook
  ci                            Set up, upgrade, and configure React Doctor in
                                your CI
  version [options]             show the version with Node and platform info
  rules                         List, explain, and configure which React Doctor
                                rules run
  experimental-lsp              [experimental] run the React Doctor language
                                server over stdio (for editors)

Examples:
  $ react-doctor                                # scan the current project
  $ react-doctor ./apps/web                     # scan a specific directory
  $ react-doctor --scope changed --base main    # scan only new issues vs. main
  $ react-doctor --project modules/a,modules/b  # score each module separately (names or paths)
  $ react-doctor --staged                       # scan staged files (pre-commit hook)
  $ react-doctor design                         # run the focused UI design audit
  $ react-doctor --category Security            # show only one diagnostic category
  $ react-doctor --blocking warning             # fail CI on warnings too (default: error)
  $ react-doctor --json > report.json           # write a machine-readable report
  $ react-doctor why src/App.tsx:42             # explain why a rule fired there
  $ react-doctor ci install                     # scan every pull request in CI
  $ react-doctor install                        # set up the agent skill and git hook

Configuration:
  Add a doctor.config.ts (or .js/.mjs/.json — or a "reactDoctor" key in your package.json) in the project root.
  Use react-doctor rules to list, explain, and configure rules. CLI flags always override config values.
