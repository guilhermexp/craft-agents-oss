Repo Reality

The original plan is directionally right, but several details do not match the current implementation.

DTO flags are half-present
`MeetingStartInput` already contains `summarizeOnEnd` and `followUpOnEnd` in `packages/shared/src/protocol/dto.ts:49-69`. `MeetingRecord` in `dto.ts:72-88` still lacks those fields plus archive and recording metadata. The `isArchived` lines cited by the original plan belong to `Session`, not `MeetingRecord`.
owner: packages/shared/src/protocol/dto.ts
Recording is not connected to meetings
`RecordingService.finalize()` returns `{ recordingId, outputPath, bytesWritten, durationMs }`, but no code updates a `MeetingRecord` or transcript after finalization. The toolbar records `.webm` independently from the MeetingService record lifecycle.
owner: apps/electron/src/main/meetings/recording-service.ts
Summarize command does not exist
`runHermesMeetPlugin` currently accepts only `start`, `status`, `transcript`, and `stop`. The plan must not call `runHermesMeetPlugin('summarize')` unless a real Hermes command is added and tested.
owner: apps/electron/src/main/meetings/meeting-service.ts

04

Service Flow

Keep the user-visible browser, Hermes bot, and Craft recorder as separate ownership domains.

Start
When `browserInstanceId` is provided and exists, set `ownsBrowserInstance: false`. When MeetingService creates a pane, set `ownsBrowserInstance: true`. Store `summarizeOnEnd` and `followUpOnEnd` on the record immediately.
owner: MeetingService.start
Stop
If Hermes capture is active, call `runHermesMeetPlugin('stop')`. Destroy the BrowserPane only when `ownsBrowserInstance === true`. Then mark stopped and trigger post-processing only when a transcript or recording is available.
owner: MeetingService.stop
Archive/delete
Archive updates record metadata only. Delete removes the record, transcript JSON, summary markdown, and the recorded media path stored under `recording.path`.
owner: MeetingService.archive/delete

Use current provider docs but keep conversion/chunking as fallback, not as the default assumption.

Provider
Status
Implementation note

Groq speech-to-text
Size risk
Use multipart form upload with `file` and `model`. Groq docs list WebM, but size limits make chunking or ffmpeg compression relevant for long calls.

Strict

Risks

These are the implementation risks that should stay visible while applying the plan.

Risk
Severity
Mitigation
Summarization backend is undefined
High
Do not call a nonexistent Hermes `summarize` command. Pick an explicit adapter before implementing AI summary/tasks.
Recording finalize lacks meeting identity
High
Return `meetingId` from prepare and pass it into finalize, or create a MeetingRecord inside prepare.
Bot auth identity confusion
High
Keep `bot-auth.json` generated by `create-meet-bot-auth.py`; do not reuse visible organizer cookies.
Long recordings exceed Groq limits
Medium
Start with direct WebM upload; add chunking or ffmpeg compression when size/provider errors require it.
Session meeting_tool remains placeholder
Medium
If product scope includes Hermes session-tool parity, add a separate task for `SessionManager` callbacks and session-tool contract tests.

Open Questions

Resolve these before implementing the final post-processing step.

Which engine generates summaries and follow-ups?
MeetingService currently has no LLM dependency. Choose Craft LLM connection, Hermes ACP session, or deterministic non-AI summary. The original Hermes plugin command is not present.
owner: product/architecture
Should archived meetings have a visible archive view?
If `list()` filters archived records by default, the UI needs either an includeArchived toggle or an unarchive path; otherwise archive is effectively one-way from the user perspective.
owner: renderer UX
Should session-scoped meeting_tool route to MeetingService?
Current callbacks in `SessionManager.ts:3386-3461` operate on BrowserPane placeholders. Leave this out of scope unless the feature promises Hermes agent control parity.
owner: session tools
